<h2>数量不是拍出来的，是算出来的</h2>
<p>「多店铺要买几个 IP」这个问题，答案取决于三件事：店铺是否属于同一经营主体、平台是否允许同主体多店、以及你是否需要为故障预留冗余。三者不同，数量差很多。</p>
<p>先说底线：从隔离角度，一个店铺对应一条独立地址。这是最保守也最清晰的做法。任何「两家店共用一条」的方案，都要有明确理由，并且要接受两条店铺在平台看来来自同一来源这一事实。</p>
<p>在这个底线之上，再考虑两件事：是否需要备用地址、是否需要给运营人员的设备单独分配。加上这两项，才是实际采购数。</p>

<h3>备用地址：要不要留，怎么留</h3>
<p>留备用是为了应对「主地址不可用」这种突发情况。但要注意，备用地址不能在需要时才第一次启用——账号从没在这条地址上登录过，突然切换，本身就是一次明显的环境变更。</p>
<p>正确做法是让备用地址在账号建立初期就参与进来：偶尔用备用环境做常规浏览，让它成为账号历史上出现过的地址。这样真正切换时，不会显得突兀。</p>
<h3>运营人员设备：不要混在店铺地址里</h3>
<p>有些团队会让运营人员的办公电脑也走店铺地址，理由是「方便管理」。这会带来两个问题：办公流量与店铺流量混在同一出口，出问题难以归因；多个人在不同设备上用一个出口，环境特征混乱。建议店铺地址只服务于店铺操作，办公网络独立。</p>

<h2>三个影响数量的现实因素</h2>
<p>第一，平台政策。部分平台允许多店铺但要求报备或缴纳保证金，部分明确限制。数量规划前先确认政策，不要用技术手段绕开规则。</p>
<p>第二，人员分工。一人管多店时，如果所有店都在同一台设备上操作，即使地址分开，设备层仍会关联。这时真正的解法是增加设备或环境，而不是增加地址。</p>
<p>第三，增长预期。半年内计划从五个店扩到十个，就不要一次买十条闲置。同段追加通常可行，先买当前需要的，扩张时再追加，能省下闲置成本。</p>

<h2>常见的错误数量决策</h2>
<p>错误一：按账号数买，不按店铺数买。同一店铺可能有多个子账号，但它们属于同一经营主体，共用一条地址是合理的。</p>
<p>错误二：为了省钱，两个店共用一条地址的不同端口。出口地址相同，隔离无效。</p>
<p>错误三：一次买太多。地址闲置不影响使用，但会拉高单位成本，也让管理变复杂。</p>
<p>错误四：不留任何冗余。主地址出问题时临时找资源，往往拿到状态不明的地址，反而更危险。</p>

<h2>采购之后的对应关系</h2>
<p>买完立刻建立对应表：店铺名称、平台、地址、绑定设备、责任人、启用日期。这张表是后续所有管理的基础。人员变动、地址更换、故障排查，都要以它为准。</p>
<p>表要定期复核。每季度对一次，确认没有交叉使用、没有闲置未记录的资源、没有已停用但仍在表里的地址。</p>

<h2>常见问答</h2>
<h3>五个店要买五条还是十条</h3>
<p>五条是底线，加一两条备用更稳妥。具体取决于主力店数量与故障容忍度。备用不宜过多，闲置成本与收益不成比例。</p>
<h3>同一主体在不同平台的店能共用地址吗</h3>
<p>技术上可以，但不建议。不同平台的判定逻辑不同，共用出口可能在一个平台没问题、在另一个平台成为关联线索。分开更清晰。</p>
<h3>买多了能退吗</h3>
<p>多数按月方案可以停用，年付通常不支持按条退订。采购时问清退订与暂停政策。</p>
<h3>地址数量够但设备不够怎么办</h3>
<p>设备不足时，隔离效果会打折扣。可以先用虚拟机或独立浏览器配置缓解，但要清楚这不如物理设备彻底。必要时减少同时运营的店铺数，而不是硬压在一台机器上。</p>
